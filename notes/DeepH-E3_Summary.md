# Summary of DeepH-E3

This document provides a summary of the DeepH-E3 framework, based on the analysis of its source code. The summary is structured into four main sections: Data Preparation, Network Architecture, Network Details, and Training Routine.

## 1. Data Preparation

The data preparation pipeline in DeepH-E3 is designed to convert DFT calculation outputs into a graph-based format suitable for the neural network. The key components are:

-   **`AijData` Dataset**: This is the main dataset class, inheriting from `torch_geometric.data.InMemoryDataset`. It manages the loading and preprocessing of the data.
-   **Input Data Format**: DeepH-E3 expects raw data from DFT calculations (like OpenMX) to be preprocessed into a specific directory structure. Each structure has its own directory containing files for atomic positions (`site_positions.dat`), elements (`element.dat`), lattice vectors (`lat.dat`), orbital types (`orbital_types.dat`), and the target matrices (`hamiltonians.h5` or `density_matrixs.h5`).
-   **Graph Construction (`get_graph`)**: The graph representation for each atomic structure is created by the `get_graph` function. A crucial aspect of DeepH-E3 is how it defines the graph edges:
    -   The edges are not determined by a simple cutoff radius. Instead, they are defined by the non-zero matrix blocks present in the DFT output (e.g., `hamiltonians.h5`).
    -   This creates a one-to-one correspondence between an edge in the graph and a specific matrix block `A_ij(R)`, where `(i, j)` are the atom indices and `R` is the periodic image vector.
    -   Each edge explicitly stores its periodic image information `(Rx, Ry, Rz, i, j)` as an `edge_key`.
-   **Edge Features**: The features for each edge (`edge_attr`) consist of the scalar distance and the 3D displacement vector between the two atoms.
-   **Target Handling (`set_mask`)**: The target matrix blocks (`Aij`) are processed and attached to the graph as edge attributes. The `set_mask` method:
    -   Takes the full Hamiltonian or density matrix.
    -   For each edge `(i, j, R)` in the graph, it extracts the corresponding matrix block `A_ij(R)`.
    -   This block is then decomposed into its irreducible representations (`e3TensorDecomp`) and flattened into a vector.
    -   This vector becomes the `label` for that edge.
    -   A `mask` is also created to identify which parts of the flattened vector are non-zero and should be included in the loss calculation.

In summary, the data preparation in DeepH-E3 results in a `torch_geometric.data.Data` object for each structure, where edges directly correspond to the matrix blocks to be predicted, and the target vectors are stored as edge attributes.

## 2. Network Architecture

The core of DeepH-E3 is the `Net` class defined in `model.py`. It is an E(3)-equivariant graph neural network designed to learn the relationship between atomic structure and the DFT Hamiltonian.

-   **Overall Structure**: The network follows a message-passing scheme. It is composed of:
    1.  A node embedding layer.
    2.  An edge feature initialization step.
    3.  A series of interaction blocks (`num_block` times).
    4.  Final linear layers to produce the output.
-   **Interaction Blocks**: Each interaction block consists of a `NodeUpdateBlock` followed by an `EdgeUpdateBlock`.
    -   `NodeUpdateBlock`: Updates node features by aggregating information from incoming edges.
    -   `EdgeUpdateBlock`: Updates edge features based on the features of the connected nodes and the previous edge features.
-   **Input**: The network takes a `torch_geometric.data.Batch` object as input, which contains the graph information (nodes, edges, positions, etc.).
-   **Output**: The `forward` method of the `Net` returns two tensors: `node_fea` (final node features) and `edge_fea` (final edge features). The `edge_fea` tensor contains the predicted irrep coefficients for each matrix block (edge) and is the primary output for constructing the Hamiltonian.

## 3. Network Details

-   **Equivariance**: The network is built using the `e3nn` library to ensure E(3)-equivariance. All operations, including linear layers, tensor products, and non-linearities, are equivariant.
-   **Node and Edge Embeddings**:
    -   Nodes are initially represented as one-hot vectors based on their atomic number, which are then embedded into a learnable scalar representation (`irreps_embed_node`).
    -   Initial edge features are derived from the interatomic distances using a `GaussianBasis` expansion.
-   **Message Passing (`EquiConv`)**: The core convolutional operation is performed by the `EquiConv` layer. It consists of:
    1.  A `SeparateWeightTensorProduct`, which is a tensor product where the weights are generated by a fully connected network (FCN) that takes the radial basis expansion of the edge length as input. This allows the interaction strength to be dependent on the distance.
    2.  A gated non-linearity (`Gate` from `e3nn`) to introduce non-linearity while preserving equivariance.
-   **Skip Connections**: The network extensively uses skip connections in both node and edge update blocks to improve gradient flow and stabilize training.
-   **Final Output**: After the interaction blocks, two separate linear layers (`lin_node` and `lin_edge`) project the final node and edge features to their output irreps (`irreps_out_node` and `irreps_out_edge`).

## 4. Training Routine

The training process is managed by the `DeepHE3Kernel` class in `kernel.py`.

-   **Optimizer**: The model is trained using the Adam optimizer.
-   **Loss Function**: The loss is a `MaskMSELoss`, which calculates the Mean Squared Error between the predicted and target irrep coefficients. The mask ensures that the loss is only computed for the non-zero components of the target vectors.
-   **Training Loop**: The training proceeds for a fixed number of epochs. In each epoch:
    1.  The model is trained on the training set. For each batch, the forward pass is computed, the loss is calculated, and the optimizer takes a step.
    2.  The model is evaluated on the validation set.
    3.  A learning rate scheduler (`RevertDecayLR`) adjusts the learning rate based on the validation loss.
    4.  The model with the best validation loss is saved.
-   **Target Transformation**: Before being used in the loss function, the network's output (`output_edge`) is transformed by an `e3TensorDecomp` object (`construct_kernel`). This object performs the inverse of the decomposition that was applied to the target matrices during data preparation, effectively reconstructing the flattened matrix block vectors from the predicted irrep coefficients.

## 5. Spherical Harmonic Convention Conversion

The conversion of spherical harmonic basis sets between the OpenMX convention and the e3nn/Wikipedia convention is handled by the `Rotate` class in `deephe3/e3modules.py`.

- The `Us_openmx2wiki` dictionary within this class stores the explicit permutation matrices required to convert the real spherical harmonic basis for angular momenta `l=0, 1, 2, 3`.
- This conversion is not done during the initial data preprocessing (i.e., not in the Julia script). Instead, it is performed on-the-fly in the Python code.
- The `e3TensorDecomp` class, which is responsible for processing the network's outputs and the target matrices, utilizes the `Rotate` class to ensure that both the predictions and the targets are in the same e3nn-compatible basis before the loss is computed.
